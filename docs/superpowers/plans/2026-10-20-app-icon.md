# App icon — implementation plan

Spec: `docs/superpowers/specs/2026-10-20-app-icon-design.md`. One branch,
`feature/app-icon`, one commit per step. Each step leaves `scripts/check.sh`
green.

## Step 1 — Icon assets

**Changes**
- `assets/icon/lopress.svg` (full mark) and `assets/icon/lopress-small.svg`
  (16/24 variant), 64×64 viewBox, `lp` as `<path>` outlines from Roboto Slab
  Bold. Outlining is a one-off authoring step (fontTools in a scratch venv);
  the SVGs record the font and licence in a comment.
- `scripts/build-icon.py`: stdlib only. Shells out to the `resvg` CLI
  (`cargo install resvg`) to render each size, then packs PNG-encoded entries
  into `lopress.ico` (ICONDIR + ICONDIRENTRY + PNG blobs).
- Generated, committed: `assets/icon/lopress.ico`, `assets/icon/lopress-256.png`.

**Proof**
- `python scripts/build-icon.py` exits 0 and rewrites both outputs.
- A stdlib check reads the ICO directory and prints sizes `16 24 32 48 64 256`;
  the PNG's IHDR says 256×256.
- Rendered 16/32/256 PNGs viewed and compared with board F on the concept sheet.

**Depends on:** nothing.

## Step 2 — Runtime window icon

**Changes**
- `crates/lopress-editor/src/app_icon.rs`: `include_bytes!` the 256 PNG;
  `pub(crate) fn window_icon() -> Option<Icon>` decodes it via `image` and
  builds `Icon::from_rgba`. Logs a warning and returns `None` on failure.
- `crates/lopress-editor/src/lib.rs`: `mod app_icon;` and apply
  `.window_icon(..)` to `win_cfg` when `Some`.
- Unit test: `window_icon()` is `Some` and the decoded image is 256×256.

**Proof:** `bash scripts/check.sh` green, including the new test.

**Depends on:** step 1 (the PNG).

## Step 3 — Exe icon resource

**Changes**
- Root `Cargo.toml`: `[build-dependencies] winresource`.
- Root `build.rs`: when `CARGO_CFG_TARGET_OS == "windows"`, embed
  `assets/icon/lopress.ico`; `cargo:rerun-if-changed` on it. No `unwrap`/
  `expect`: errors propagate from `main() -> Result`.

**Proof**
- `bash scripts/check.sh` green.
- `cargo build`, then extract the associated icon from
  `target/debug/lopress.exe` (PowerShell `System.Drawing.Icon`) to a PNG and
  view it: it is the lopress mark, not the generic icon.
- The user runs `cargo run` and confirms the taskbar.

**Depends on:** step 1 (the ICO). Independent of step 2.

## Not doing

- Site favicons (separate feature).
- macOS `.icns` / Linux `.desktop` packaging.
- Rasterizing at build time.
